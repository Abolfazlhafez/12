# کارگاه‌یار (Karegah-Yar)

اپلیکیشن مدیریت کارگاه ساختمانی، آفلاین-محور، ساخته‌شده با React + TypeScript + MUI v5 +
Dexie/IndexedDB و Capacitor (اندروید).

## پیش‌نیازها

- Node.js نسخه ۲۰ یا بالاتر
- npm

## اجرای محلی

```bash
npm ci
npm run dev          # اجرای نسخهٔ توسعه در مرورگر
npm run build         # بررسی TypeScript + بیلد نهایی وب در dist/
npm run lint           # بررسی Lint (oxlint)
```

## شروع سریع — Push به گیت‌هاب و ساخت APK

این پروژه یک Workflow آماده در `.github/workflows/build-apk.yml` دارد که با هر Push به
شاخهٔ `main`، به‌صورت خودکار پروژه را بیلد کرده و یک APK امضاشده می‌سازد.

### با GitHub Desktop (روش پیشنهادی)

1. پوشهٔ استخراج‌شدهٔ این پروژه را در GitHub Desktop باز کنید:
   `File → Add Local Repository…` و مسیر این پوشه را انتخاب کنید.
2. **اگر مخزن گیت‌هاب هنوز ساخته نشده:** دکمهٔ **Publish repository** را بزنید.
   حتماً گزینهٔ **Keep this code private** را فعال نگه دارید (دلیلش در بخش
   «نکتهٔ امنیتی» پایین همین فایل توضیح داده شده).
3. **اگر مخزن از قبل وجود دارد:** تغییرات به‌صورت خودکار در تب Changes دیده می‌شوند؛
   یک توضیح کوتاه در قسمت Summary بنویسید و **Commit to main** را بزنید، سپس
   **Push origin** را بزنید.
4. به مخزن پروژه در وب‌سایت گیت‌هاب بروید → تب **Actions** → اجرای در حال انجام
   («Build Android APK») را ببینید. حدود ۵ تا ۱۰ دقیقه طول می‌کشد.
5. وقتی اجرا با علامت سبز تمام شد، روی همان اجرا کلیک کنید؛ در پایین صفحه بخش
   **Artifacts** یک فایل به نام `karegah-yar-apk` است — آن را دانلود کنید
   (یک فایل zip است)، از حالت فشرده خارج کنید تا فایل `.apk` واقعی به دست بیاید،
   و آن را به گوشی اندروید منتقل و نصب کنید.

### با خط فرمان Git

```bash
git init
git add .
git commit -m "به‌روزرسانی پروژه"
git branch -M main
git remote add origin <آدرس-مخزن-گیت‌هاب-شما>
git push -u origin main
```

(اگر مخزن از قبل وصل است، مراحل `init`/`remote add` را رد کنید و فقط
`git add . && git commit -m "..." && git push` کافی است.)

## نکتهٔ مهم — versionCode قبل از هر Push جدید

فایل `android/app/build.gradle` مقدار `versionCode` را دارد. اندروید نصب یک نسخهٔ
جدید را روی نسخهٔ نصب‌شدهٔ قبلی فقط زمانی Update حساب می‌کند که این عدد از قبلی
**بزرگ‌تر** باشد. پیش از هر Push که قرار است روی نصب فعلی گوشی‌ها Update بخورد،
این عدد را دست‌کم یک واحد افزایش دهید (`versionName` صرفاً نمایشی است و لازم
نیست حتماً تغییر کند).

## نکتهٔ امنیتی — کیستور امضای Release

فایل `android/app/karegah-yar-release.keystore` و رمز آن (در
`android/app/build.gradle`) عمداً همراه پروژه Commit می‌شوند تا همهٔ نسخه‌های
Release با یک کلید یکسان امضا شوند (در غیر این صورت، هر Push نصب Update را
روی نسخهٔ قبلی رد می‌کرد). **پیامد این تصمیم:** هرکسی که به این مخزن گیت‌هاب
دسترسی بخواند داشته باشد، هم کیستور و هم رمز آن را می‌بیند. به همین دلیل:

- مخزن را حتماً **Private** نگه دارید.
- اگر روزی خواستید این مخزن را Public کنید یا با کسی دیگر Share کنید، بهتر
  است پیش از آن، کیستور و رمزش را از کد خارج کرده و به‌جای آن از
  GitHub Actions Secrets استفاده کنید — در صورت نیاز می‌توانم این تغییر را
  هم برایتان انجام بدهم.
